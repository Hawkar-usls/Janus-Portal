# R12 — исправление зависшего каталога 360° и подключение Google Street View

**Дата:** 2026-11-22. **Репорт владельца:** скриншот с застрявшим `⏳ Проверяем доступные 360°…` в исходном `#originChoice` и кнопкой «Обновить», похожей на неоформленную HTML-кнопку. Запрос: «не обновляет, так же вшей нам демо ключ чтоб мы могли и гугл стрит юзать».

## Исследование причины

Сразу после выкладки R11 сайт GitHub Pages отдавал HTML, `src/app.js` и `src/styles.css` по прежним постоянным URL с заголовком **`Cache-Control: max-age=600` (10 минут)**. Поскольку HTML и JS/CSS кешируются независимо, браузер мог получить R11 HTML, но исполнять R10/предыдущий JS и CSS. В таком сочетании R11-список остаётся в HTML-плейсхолдере «Проверяем…», JS предыдущей версии не знает о `originCatalog`, а новая кнопка выглядит как браузерная стандартная. **Это сильное техническое объяснение скриншота, но конкретный кеш пользователя удалённо не диагностирован.** На другом Edge с холодным кешем ранее R11 возвращал 19 из 38 регионов.

Второй дефект: в R11 кнопка `Обновить` блокировалась пока шли 38 сетевых проверок. При блокировке Panoramax 38 × 8 сек с четырьмя worker могли занять до ~80 сек, без явного общего дедлайна. Вложенные ошибки превращались в пустой список, но прогресс не был достаточно явным.

## R12 исправление

1. **SHA-версия двух веб-ресурсов:** GitHub Pages workflow на этапе сборки *копии* `dist/index.html` вставляет `?build=$GITHUB_SHA` в оба пути `./src/app.js` и `./src/styles.css`. Оба получают один commit SHA каждого релиза; при новой публикации URL обоих меняются одновременно. Исходный `index.html` оставляет прежний R2 `./src/app.js`, поэтому работающий source graph и 5 импортов не меняются. CDN Pages может кешировать HTML на 600 сек, но новый HTML больше не может смешать старый JS с новым CSS из-за постоянного URL.
2. **18-секундный предел на полный каталог:** `LIVE_MAX_SCAN_MS=18000`; таймер прерывает текущие запросы. Статус выводит реальное количество проверенных регионов, частичный список либо ошибку/тайм-аут, не выдаёт отсутствие сети за отсутствие фотопанорам.
3. **Кнопка повтора остаётся доступной:** `refreshCoverageBtn` активна пока грузятся API-данные. Следующее нажатие отменяет прежнее поколение запросов; старые результаты не могут попасть в новый список благодаря `liveGeneration`. Защита от случайных быстрых кликов в 1,5 сек. Если источник вернул ошибки для всех 38 районов, видна явная ошибка и инструкция проверить доступ к `api.panoramax.xyz`.
4. **Google Street View только через разрешённый ключ владельца:** в единственной панели настроек появилась официальная ссылка https://developers.google.com/maps/documentation/javascript/get-api-key , пояснение о ключе с ограничением по `https://hawkar-usls.github.io/*`, Maps JavaScript API, биллинге и квотах. **Google Maps Demo Key — реальная бесплатная функция, но список её разрешённых API/JS-функций не включает Street View.** Нельзя вставить выдуманный/чужой общий ключ или скопировать частный ключ в публичный GitHub. Существующий GoogleProvider работает с введённым владельцем браузерным ключом; статус реальной авторизованной Google-панорамы пока **НЕ ПРОВЕРЕН**, поскольку такого ключа нет в этом запуске. Пользовательский ключ не хранится в репозитории и не сохраняется нашим приложением.
5. **Никакого нового просмотра:** один `#originChoice`, одна `#viewer`, исходные 5 R2-импортов, естественное движение камеры, полноэкранный R10, реальные Panoramax снимки и лицензии — без изменений. R11 не показывает неподтверждённые географические точки и не выдаёт старые источники за live.

## Проверки

- `npm run verify`: **50/50 PASS** (5 новых офлайн регрессий + 45 предыдущих).
- `tools/browser-catalogue-r12-check.mjs`: проверяет настоящую/версионированную загрузку JS и CSS, computed style кнопки, HTTP 503 источника, повтор и восстановление подтверждённой точки Феса, отсутствие ложного старого списка, 18-секундную остановку полностью зависшего источника на мобильном, доступность Google настройки без фиктивного общего ключа.
- `tools/browser-live-catalogue-r11-check.mjs`: поддерживает версию `?build=<40-char git SHA>` на публичном сайте и подтверждает настоящую 360° панораму Феса, переключение/отказ источника, полноэкранный режим и нулевые ошибки JavaScript.
- **Статус публикации:** PR CI → main merge → Pages Success → проверить реальные `?build=SHA` на HTTPS и R12/R11 Edge-сценарии → пользовательская проверка. Не объявлять PASS до фактических результатов.

## Дополнительные ограничения

- Кеш GitHub Pages по-прежнему может задерживать обновление **HTML** до 10 минут для ранее открытого адреса. Новый вариант URL для пользователя `?r12=<build>` вынуждает повторную загрузку HTML, а SHA-версии обеспечивают одинаковые JS и CSS. При необходимости пользователь может нажать Ctrl+F5. Время обновления каталога 5 минут касается периодических API-проверок *при незапущенном путешествии*, не гарантирует доступность Panoramax в сети пользователя.
- Нельзя автоматически генерировать Google Cloud API-ключи без действий владельца в его Google-аккаунте, настроек API, ограничений по referrer/квот и разрешённого платёжного профиля. Никогда не записывать чужой или личный ключ в issue, логи, тесты, .env или репозиторий.
- Для более широкого каталога нужны официальные проверяемые источники; эти 38 районов — известные точки проверки, не полный мир.
