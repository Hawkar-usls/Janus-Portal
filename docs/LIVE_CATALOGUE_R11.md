# JANUS PORTAL R11 — живой каталог доступных 360° без случайных и непроверенных пунктов

**Дата:** 22 ноября 2026 года. **Требование пользователя:** удалить оба «Случайный...» пункта из списка старта и показывать только места, где доступные 360° подтверждаются актуальным запросом к источнику. Не добавлять второй поиск, не выводить чужие туры вне JANUS и не ломать работающий R2/R10.

## Поведение

- **Оба случайных пункта удалены полностью:** `random`, `random-verified`. Режим «Как выбирать точки интереса → Без анализа · случайные взгляды» не относится к выбору стран и остаётся: это случайные *повороты камеры внутри уже открытой панорамы*.
- Единственное выпадающее меню **«Откуда начинаем»** теперь изначально пустое/неактивное с надписью «Проверяем доступные 360°». Список из 38 *кандидатных координат* хранится в инертном HTML `<template id="originCatalog">`; он не показывается пользователю как подтверждённый.
- При загрузке страницы `probePanoramaxCoverage()` получает **новые** ответы публичного Panoramax API для **каждого из 38 известных стартовых районов**; один сетевой запрос (`bboxAround(origin, 1.2 км)`, `limit=120`, `cache=no-store`) на район, максимум **4 одновременных**, тайм-аут **8 секунд**. Из метаданных принимаются только equirectangular/FOV≥300 панорамы с реальным ID, collection, URL изображения и географической дистанцией не более 5 км от стартовой точки. 2D, дальние и без изображения исключаются.
- Выпадающий список дополняется только подтверждёнными в **текущем сеансе** пунктами; по завершении показывает количество, локальное время проверки, ошибки сети. **Нет сохранения старых положительных результатов** в localStorage или статического резервного набора. При ошибке района он не отображается.
- Каталог перечитывается по кнопке **«⟳ Обновить»**, при загрузке, при возврате видимой вкладки и далее **каждые 5 минут**, если страница активна и пользователь не запустил экспедицию. После остановки длительной экспедиции проверка возобновляется по истечении интервала. Это **периодический запрос живого API**, а не непрерывный поток изменений или полное покрытие всей планеты.
- При нажатии «▶ Запустить» **первым** открывается именно найденный при текущем live-запросе 360° кандидат (если ещё не посещён и лежит в текущем радиусе); только затем включается прежний R2-алгоритм переходов и естественный осмотр. **Никаких новых J Coins или двойных посещений**. Если подтверждённая метаданными фотография фактически не загрузилась, визит не засчитывается, точка удаляется из текущего списка до нового обновления.
- **Ручные координаты** вынесены в раскрываемый блок: они не маскируются под «доступное место» и всегда требуют реального поиска. **Google Street View:** автоматическое перечисление недоступно без официального ограниченного API-ключа и могло бы породить оплачиваемые запросы. Поэтому при выборе Google список населённых пунктов не выдаётся за подтверждённый Google; доступен только явный ручной поиск по координатам после ввода ключа.
- Нет прямой авторитетной верификации географической подлинности изображений, которую Panoramax не предоставляет. Метаданные могут быть неверно геотегированы или изображения могут быть удалены между проверкой и запуском. Честная формулировка: «подтверждено в каталоге API при проверке», не «все районы планеты» и не «каждая геометка независимо доказана».

## Фактическое покрытие и тесты

На Yaksa/Edge (22.11.2026) живой API вернул **19/38** доступных кандидатных районов: Париж, Ренн, Лион, Токио, Нью-Йорк, Пуна, Катманду, Фес, Мерзуга, Себу, окрестности Себу, три района Пенанга и пять районов Куэнки. Отсутствовали Пхеньян, Каир, Гиза, Найроби, Лагос и другие, для которых свежая выборка не показала подходящего 360°. Эти **19** — не 19 уникальных фотографий и не гарантия постоянного покрытия.
 
- `npm run verify`: **45/45 PASS** — сохранность первоначальных пяти R2 модулей, полноэкранного R10, live-фильтрация 360/FOV/assets/distance, запрет случайных пунктов, проверка отказа API и раздельного Google.
- `tools/browser-live-catalogue-r11-check.mjs` (optional Playwright): **настоящий Edge** открыл страничку и дождался всех 38 свежих запросов; в выпадающем списке оказалось **19/38** подходящих мест, никакой КНДР/Каир. Первым прыжком сразу показана настоящая лицензированная 360° фотография Феса `34.06167,-4.97711`, режим «На весь экран / Свернуть» PASS, JS errors **0**.
- **Детерминированные имитации API:** сначала Фес — единственный доступный город; после следующей live-проверки Фес исчезает и появляется Катманду; после пустых результатов список пустой и старт заблокирован; при HTTP 503 старый список **не** возвращается; Google без ключа не запускает платный фоновый каталог; мобильный экран 390px работает, JS errors 0.
- Старый `./src/app.js`, ровно **5 импортов**, действующий Panoramax/Google viewer, 5→10→…→20 000км экспедиция, fullscreen, счётчики/история и server-only J Coins не менялись. **Нет нового runtime-модуля**.

## Что остаётся открытым

- Автоподбор **всех новых стран мира**, а не только известных 38: нужен источник с проверенными глобальными индексами 360° и контролем достоверности географии; в R11 это не реализовано.
- Автоматическое подтверждение Google-покрытия потребовало бы отдельного разрешённого бюджета и добровольного включения. Сейчас Google только ручной поиск.
- Личная проверка владельца после публикации важнее даже успешной Edge/CI репликации (старые R3–R5 версии ломались в его браузере).
- Любые 360° в Каире, Северной Корее и малых поселениях Африки должны добавляться только из реального источника с лицензией и работающим просмотром внутри JANUS, а не через фиктивный статический пункт.
