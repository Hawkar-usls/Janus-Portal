# JANUS PORTAL emergency rollback to first public working R2

Date: 2026-11-22. User reported that latest R5 rendered the page and styling but displayed: "Код Портала не загрузился" and none of the buttons worked. Their screenshot shows a late watchdog message, not the original JavaScript error or failed network request.

## Decision and baseline

**Restore original first successfully published R2 application tree** from commit
`1b34bff74e2239d34cbdc09c1753df1041d63dc2` (just before R3 tours/fullscreen).
This restores the HTML entrypoint `./src/app.js`, the R2 Panoramax provider,
original gaze/viewer, CSS and original Pages workflow with `dist/src` assets.
It intentionally removes R3–R5 features from production until they are isolated and retested with the user's browser.

**All abandoned changes have NOT been deleted:** archived untouched R5 main at
`archive/r5-before-r2-rollback-20261122`, head `20fd3848927b4e93346498df95eddaaa6e88aed1`.
To recover future work, branch from this archive and cherry-pick *one change at a time*.

## Evidence

- Clean local checkout of R2 at the exact source commit passed `npm run verify` (23/23).
- Edge Playwright opened the original source on http://127.0.0.1:4191/.
  Click on the ordinary "Запустить" opened a REAL Panoramax 360° photo near Paris
  at `48.85723, 2.36881`, unique count 1, status `Живой взгляд`, gaze `Осматривается`, no JavaScript exceptions.
- Main R5 also passed on the independent Yaksa device, **so we cannot claim** that R5 was reproducibly broken everywhere.
- R2 uses a short import graph and static `./src/*.js`. Later R3–R5 added multiple modules and R5 switched to `./assets/<revision>/*.js`. A failed module import, a stale or unavailable revisioned asset, local browser filtering, runtime exceptions or storage permissions can all prevent module initialization while CSS renders normally.
- The watchdog in late R5 only established that `window.__JANUS_PORTAL_READY__` was not set within 6.5 seconds. It does NOT prove which script or import failed, nor that `github.io` itself was blocked.

## Independent release gates

1. Verify GitHub Pages actually deploys this rollback, not merely green unit CI.
2. Check public `index.html` imports `./src/app.js` (NOT revisioned `assets`), that both JS and CSS return HTTP 200, and that opening a panorama from the public URL works in a fresh Edge browser.
3. Ask user to test the exact same public URL. The rollback is not proven to resolve their device until the user confirms it.
4. If R2 still fails on the user's side, capture browser console/network error before any more code changes. A single screenshot of a generic watchdog is insufficient to identify a cause. Do not repeatedly create experimental viewers or deployments.
5. Restore tours/fullscreen/extreme tourism only behind separate branches and after isolated, user-confirmed browser checks.

The client J Coins logic remains intentionally disabled. No personal Google credentials or paid Google APIs are used by this rollback.
