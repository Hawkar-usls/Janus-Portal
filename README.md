## R13 — все бесплатные 360° источники объединены по местам, без выбора провайдера

В JANUS PORTAL теперь **нет видимого выбора Panoramax / KartaView / Wikimedia Commons**. Выбираешь **географическое место** и нажимаешь обычную **«▶ Запустить»** — приложение само подбирает реальную 360° фотографию из **трёх подключённых источников**. «⟳ Обновить» запускает проверку всех трёх одновременно в одном общем цикле. В списке остаются только места с текущими подходящими source-метаданными. Никаких случайных пунктов или отдельных окон.

Новые **KartaView** и **Wikimedia Commons** фото открываются **непосредственно в большом окне JANUS** через лёгкий WebGL сферический рендерер без новых скриптов/библиотек; источник, автор и лицензия показаны в самом окне. Panoramax продолжает работать через старый официальный R2 плеер. Доступны прежние движения камеры, «Пауза», «На весь экран» / «Свернуть», журнал и карта. Если одна фотография не загрузилась, JANUS может выбрать другой подтверждённый источник того же района — без ложных посещений.

В Edge **55/55 тестов PASS** и реальный общий поиск на известных координатах дал **20 географических регионов** (Panoramax 19, KartaView 7, Wikimedia Commons 1; эти числа **перекрываются**, а не складываются). Реально просмотрены 360° снимки Феса (KartaView) и Сан-Диего (Wikimedia Commons), с корректной ориентацией и атрибуцией.

**Ограничения:** массовая проверка охватывает **39 известных стартовых районов**, а не всю Землю. **Google Street View** не входит в автоматическое массовое сканирование, потому что его официальный API платный: он может добавляться в явный **ручной поиск** только со своим ограниченным ключом и отдельным согласием (не более четырёх запросов за одну ручную экспедицию). **Mapillary** требует собственного токена разработчика и пока не включён в готовый миксер. Изображения 2D исключаются; точность исходных геометок не гарантирована.

Технические данные, источники лицензий, реальные браузерные доказательства: [docs/MIXED_SOURCES_R13.md](docs/MIXED_SOURCES_R13.md).

## R12 — каталог не зависает, Google Street View подключается официальным ключом

Исправлена проблема «⏳ Проверяем доступные 360°…» после обновления Портала. **GitHub Pages кеширует JS и CSS 10 минут**, поэтому новый HTML мог запускаться со старыми файлами. При каждой публикации Pages теперь автоматически добавляет **одинаковый SHA версии** к адресам `src/app.js` и `src/styles.css` в опубликованной странице. Рабочие пути оригинальной R2 и пять её импортов в исходниках не меняются.

Каталог Panoramax по-прежнему показывает только 360° места, подтверждённые свежим ответом API, но теперь весь цикл проверки ограничен **18 секундами**. При ошибке сети или тайм-ауте появляется понятное сообщение; **«⟳ Обновить» доступна и во время поиска** для повторного запроса, причём устаревшие ответы прежнего запроса не попадут в новый список.

В настройках Google Street View дана [официальная инструкция по получению и ограничению ключа](https://developers.google.com/maps/documentation/javascript/get-api-key). **Бесплатный Google Maps Demo Key не поддерживает Street View** — нужен собственный браузерный Google Cloud Maps JavaScript API-ключ с разрешениями, квотами и биллингом. Выдуманный или чужой ключ в репозиторий не добавлялся; ключ вводится в Портале только на время открытой страницы.

Тесты: **50/50 PASS**; реальный Edge: ошибка Panoramax → повтор → восстановление списка, полностью зависший источник → сообщение спустя 18 секунд; без потери R9 поиска и R10 полноэкранного режима. Технический разбор: [docs/CATALOGUE_CACHE_R12.md](docs/CATALOGUE_CACHE_R12.md).

## R11 — каталог доступных 360° обновляется с Panoramax

В **единственном** меню «Откуда начинаем» **удалены оба случайных варианта**. Вместо старого длинного списка неподтверждённых городов теперь показываются только те из **38 заранее известных районов**, где **при текущей проверке** публичный Panoramax API возвращает 360° метаданные и адрес фотографии.

При каждом открытии сайта список наполняется после живого API-запроса; рядом показаны счётчик проверенных/доступных районов, время и кнопка **«⟳ Обновить»**. Вкладка обновляет данные **каждые пять минут**, когда экспедиция не идёт; также после возвращения во вкладку и после остановки длительного путешествия. При отсутствии данных или HTTP-ошибке старые записи **не** выдаются за доступные.

После выбора региона **«▶ Запустить»** сначала открывает **конкретную найденную фотографию** непосредственно в обычном окне JANUS; сохраняются естественный взгляд, карта, история и **«На весь экран / Свернуть»**. Если реальная фотография не загрузилась, визит не записывается, а место исключается до следующей проверки.

**Свои координаты** — отдельный раскрываемый ручной поиск, не рекламируемый как подтверждённое место. **Google** не перебирает автоматически множество платных Street View API-запросов: с ограниченным браузерным ключом он доступен только через ручной выбор координат.

При тестировании в Edge (22.11.2026) свежий каталог подтвердил **19 из 38** стартовых районов; Каир и Северная Корея туда не попали. Это **не** доказательство отсутствия панорам во всей стране и **не** независимая проверка подлинности геотегов. За пределами 38 известных точек автоматическое глобальное обнаружение пока не реализовано.

**45/45 офлайн-тестов и браузерный сценарий на реальном Panoramax 360°** прошли. Подробности и воспроизводимые тесты: [docs/LIVE_CATALOGUE_R11.md](docs/LIVE_CATALOGUE_R11.md).

## R10 — полноэкранный просмотр панорам

В верхней части **того же основного окна JANUS** добавлена кнопка **«⛶ На весь экран»**. Она разворачивает текущую 360° панораму (вместе с её заголовком и статусом), а после нажатия **«Свернуть»** возвращает исходный вид без потери фотографии или маршрута. В системном полноэкранном режиме также работает стандартный **Esc**.

На мобильных браузерах, не разрешающих HTML Fullscreen API (в том числе некоторых версиях iOS Safari), включается **разворачивание во всю область браузера** с собственной кнопкой выхода и поддержкой Esc. Это честный fallback: он не обязательно скрывает адресную строку браузера.

**Сохранены** единый поиск R9, прежняя кнопка `▶ Запустить`, оригинальный `./src/app.js` и ровно пять старых импортов R2. Никакого нового просмотрщика, загрузчика, CDN или внешней страницы нет. Реальная Panoramax 360° фотография продолжает отображаться внутри **`#viewer`**.

Проверки: **39/39** офлайн-тестов, Edge на реальной панораме Феса, системный полноэкранный режим/выход, мобильный вариант и выход через Esc. Подробности: [docs/FULLSCREEN_R10.md](docs/FULLSCREEN_R10.md).

# 🌍 JANUS PORTAL

**Автоматическая 360°-экспедиция по миру.** Игровой скринсейвер JANUS: персонаж осматривается в реальной панораме, затем прыгает к ещё не посещённой ближайшей доступной точке. Если подходящих точек нет в пределах выбранного радиуса, поиск **автоматически расширяется**.

> **Статус:** опубликован экспериментальный веб-MVP: **https://hawkar-usls.github.io/Janus-Portal/**. Реальный Panoramax и R2 движок естественного взгляда проверены в Edge; GitHub Actions unit PASS. Вход пользователя, серверные J Coins, Google live E2E и вкладка на основном сайте ещё требуют интеграции. Не выдавайте локальные посещения за оплаченные.

## Функции

- **Начальный радиус 5 км:** последовательность **5 → 10 → 20 → 40 → 80 → … → 20 000 км** при отсутствии нового результата.
- Выбор стартового города или координат; ручной прыжок.
- **Panoramax:** открытые панорамы 360°, поиск через официальный STAC API, просмотр через официальный web-viewer, сохранение локальной истории.
- **Google Street View:** подключение через официальный Maps JavaScript API с отдельным **ограниченным браузерным ключом**; запросы и загрузка могут тарифицироваться. Google-derived геоданные остаются **только в текущей сессии** до проверки политики хранения.
- Время на осмотр 2–30 секунд; переключатель **турбо ×2**; пауза/продолжение/остановка.
- Фильтрация по ID источника **и по близости координат** (~20 м), чтобы не открывать одно место многократно.
- Счётчики уникальных посещений, успешных прыжков и суммарного расстояния по прямой; карта на Leaflet/OpenStreetMap для Panoramax-истории.
- Экспорт JSON, локальные достижения. **JC всегда «—» до серверного подтверждения; локальный клиент не может чеканить монеты.**

## R2 — живой взгляд, а не механическое вращение

После загрузки панорамы самостоятельный `GazeDirector` плавно поворачивает камеру, оглядывается, ненадолго замирает, возвращается к увиденным деталям, выполняет плавный зум («прищуривание»), потом возвращает широкий обзор. Длительность **случайна для каждой точки** и увеличивается с количеством/оценкой интересных деталей. Настройки: естественный/мягкий/статичный осмотр, анализ контраста/локальная ML/без анализа, базовое время 5–60 секунд, турбо ×2.

**Panoramax:** изображение (в памяти браузера) используется для оценки контраста и, если пользователь выбрал режим, для локальной MediaPipe EfficientDet-Lite0 детекции объектов, включая `person`. Результат вероятностный, не гарантирует точного наведения на объект или обнаружения всех людей. Никакой идентификации людей. Библиотека и веса модели загружаются из CDN; поставщик MediaPipe может собирать технические метрики использования. Фото не отправляются в JANUS.

**Google Street View:** только движение официальной камеры, **без** извлечения пикселей, классификации людей, скачивания снимков или наложения Google-координат на OSM.

Для локального браузерного smoke-теста можно использовать `tools/browser-gaze-check.mjs` (требует установленный Playwright и отдельный работающий `npm run dev`). Подробности: [docs/HUMAN_GAZE_R2.md](docs/HUMAN_GAZE_R2.md). **Browser PASS Panoramax ≠ Google browser PASS**.

## Быстрый старт

Требуется Node.js 20+:

```bash
git clone https://github.com/Hawkar-usls/Janus-Portal.git
cd Janus-Portal
npm run verify
npm run dev
```

Откройте **http://127.0.0.1:4173**. Используйте локальный HTTP-сервер, не открывайте `index.html` как `file://`: ES modules и браузерные API могут блокироваться.

**Без Node:** любой статический HTTP-сервер, обслуживающий `index.html` и `src/`.

### Google-режим

Google Maps JavaScript API со Street View нужно включить в Google Cloud, настроить биллинг, ограничение ключа по **HTTP referrers** для вашего конкретного домена и **API restrictions**, а также бюджет/квоты. Ключ в репозиторий, README, issue, Actions лог или историю коммитов **не вставлять**. Для локальной разработки нужен отдельный ограниченный ключ. При подозрении на утечку — ротировать.

Ключ вводится во время запуска в интерфейсе и не пишется в localStorage. В Google-режиме панорама показывается официальным виджетом с его атрибуцией; содержимое Street View не скачивается и не перепубликуется. Сведения Google о местах сохраняются только в памяти текущей вкладки; в карту OSM попадают только Panoramax-данные. Перед постоянным хранением и объединением с глобальным рейтингом — проверить актуальные Google Maps Platform Terms.

### Публикация GitHub Pages

Workflow `.github/workflows/pages.yml` публикует **только** `index.html` и нужные `src/*` после push в `main`. **Pages включён и использует GitHub Actions.** Проверенная публикация R2: [JANUS PORTAL](https://hawkar-usls.github.io/Janus-Portal/), workflow [45012393984](https://github.com/Hawkar-usls/Janus-Portal/actions/runs/45012393984) PASS после добавления всех JS-модулей и задержки для индексации артефакта. После следующих изменений подтверждайте состояние нового workflow; успешный предыдущий run не гарантирует успешность следующего.

## Как выбирается следующее место

1. Ищем новые панорамы **в радиусе 5 км** (или выбранном пользователем).
2. Отбрасываем уже открытые ID, координаты ближе 20 м к ранее посещённым и варианты вне радиуса.
3. Случайно выбираем одну из ближайших допустимых точек (из пула до 6).
4. Если подходящих результатов нет, расширяем радиус ×2 и повторяем. После достижения 20 000 км или ошибки API — честно сообщаем об ограничении, **не заявляем, что все панорамы Земли исчерпаны**.
5. Записываем посещение **только после успешной загрузки панорамы**. Пока нет backend — в локальную историю, без начисления JC.

Поиск использует ограниченные выборки источников: это **вероятностная разведка**, не исчерпывающий перебор всех панорам. В редких случаях 360° изображение может не загрузиться: оно не должно давать монет и не считается успешным открытием. При изменении или прекращении работы внешних API повторите браузерный smoke-test.
